# Reference-guided regeneration — mandatory when user asks to recreate an image

## Why this mode exists

A full-page screenshot is not a clean reusable artwork. Naive crops of a character cut off limbs and preserve old text; CSS blur and gradients layered on top of baked-in glow introduce haze. When the user explicitly asks to **recreate** the visual from the reference, use image generation *conditioned on the actual cropped reference and a detailed prompt*, not extraction-as-final-output. The cropped component is an **input reference** only, never the newly delivered artwork.

A rendered reference can guide fidelity, but cannot guarantee a 100% identical generation. Compare, diagnose and iterate; disclose residual deviations. Never claim pixel-perfect based on a plausible prompt or a model-generated image alone.

## Exact two-stage sequence demonstrated in the user video

1. **Reference and composition**. Inspect the *full original screenshot* and make an isolated **reference crop** of the target visual area. Keep the full screenshot and crop as visual inputs to the image-generating agent. Record their paths, SHA-256, coordinates, scale and target aspect ratio. The crop may contain text or partially hidden anatomy; that is *not* authorization to reproduce baked text or to crop the resulting asset. The crop is a visual guide.
2. **Image-to-prompt forensic description**. Produce `artifacts/regeneration/scene-prompt.md` from the actual visual (not generic genre prompting). Describe subject identity, head/body proportions, ears, eyes, eyelashes, muzzle, mouth, collar/pedant, number and visibility of paws, pose, face angle and expression; camera and framing; background gradients, material, ribbons/streaks and particles; **illumination baked into the composition**, crisp highlights vs soft bloom; color palette; image dimensions/aspect ratio; and negative constraints. Distinguish observed, inferred and unknown attributes. Identify elements **not** part of the scene, including source UI, buttons, text, status bars, phone frames and overlay labels. If the source does not show a hidden part, instruct a natural anatomical continuation, explicitly marked inferred. Do not introduce additional hats, bows, garments, hair, different eye colors, humanoid anatomy or devices.
3. **Generate the scene FIRST, without typography or UI**. Invoke a connected image-generation capability with the **reference crop and full source image** as image references, plus the exact scene prompt. Require one uninterrupted scene with subject and paws visible, lights integrated into the scene, no artificial rectangular borders and no textual glyphs. Preserve the intended area for later text. Do not claim generation happened without an actual returned image. If the agent lacks image generation, STOP and report the blocker—do **not** secretly substitute a screenshot crop or a CSS-only stand-in as a regenerated image.
4. **Iterate against the original**. Open each result and compare against the reference by aligned regions. Focus on identity, eye/lash geometry, fur, ears, smile, collar, visible paws, environmental ribbons and glow, camera, balance, anatomical correctness and clear text-safe regions. Use an independent review if available. Re-prompt to fix specific mismatches instead of appending generic adjectives. Reject all failures; maintain `attempts` with images and failure notes. Minimum final review categories: `subject_identity`, `anatomy_paws`, `integrated_lighting`, `composition`, `scene_continuity`, `text_and_ui_absence` — all must be `pass` with evidence. The review process is judgment-based and cannot be fully automated by a hash validator. See `examples/catty-regeneration.contract.template.json` for an intentionally unapproved starter contract.
5. **Only THEN restore the typography exactly**. Derive the *actual wording*, font candidates, weight, size, line-height, letter-spacing, position and max-width from the original screenshot. On a webpage, implement real, accessible HTML/CSS overlay above the artwork (not image-generated raster text), using matched breakpoints and responsive art direction. For an explicitly requested *static poster/image export*, a second image-editing pass may place text on the **same generated scene**, but the text must not change the subject/scene, and the output must be checked character-by-character. Keep the scene-only master regardless. Logos/buttons are interactive HTML in a web implementation; do not bake a fake interactive CTA into the background.
6. **Final acceptance**. Compare: original screenshot vs generated scene (subject, light and framing); original screenshot vs rendered HTML/CSS with text and controls (geometry and exact copy). Present mobile + tablet side-by-side, and desktop original + rebuilt when source is a desktop screenshot. Write `artifacts/regeneration/contract.json`; validate it using `scripts/validate_generation_cycle.py --file ... --root ...` **before claiming readiness**. The validator checks documented files/provenance/review completeness, not visual equality. Run the existing asset and screenshot quality gates too.

## Asset / code boundary

- The final **scene** includes its native luminous ribbons, highlights, bloom and character; never duplicate those baked-in effects with CSS filters, gradients or a copied blurred image of the scene. Optional CSS treatment outside the scene must be non-overlapping, minimal and documented.
- The screenshot crop stays in `artifacts/reference/` as a **non-shipping input**. The generated **scene-only image** goes under `public/assets/...` (or the project-equivalent assets directory), and is not a renamed crop.
- Do not alter source assets that the user explicitly wants preserved. Regeneration is enabled only by explicit user request, chosen fallback authorization or a clear task requiring new generated art; otherwise preserve the approved original.
- A two-stage **visual** process does not remove the requirement to construct components, typography, interactions or the responsive layout in code.

## Concrete Catty failure mode

Reference: cream-colored fluffy **quadrupedal kitten**, oversized warm brown/amber eyes, black lashes, small pink nose, playful open mouth, black collar with metal heart, one visible paw, warm coral/red cinematic bokeh and ribbons. Keep her recognizable and physically continuous. Reject generated images with brown human hair, humanoid proportions, a bow, pink eyes, a different necklace, a phone being held, or fabricated UI text. Those are identity and composition failures even when the image looks polished. The scene-only first pass must reproduce the glow and preserve the visible paw; the second pass restores the precise approved headline and description *without changing the generated illustration*. See `examples/catty-hero-scene-prompt.md`.
