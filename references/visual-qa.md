# Visual fidelity QA

## Before claiming fidelity

- The render screenshot and source must correspond to the same viewport, DPR, route, text content and interaction state.
- Ensure web fonts and images loaded before capture. Avoid layout drift due to animations. Record conditions.
- Inspect raster difference and overlay. Pixel differences can come from rendering engine, font antialiasing, dynamic content or mismatch in screenshot crop.
- Do not hide problematic regions with masks. Exclude only legitimate dynamic areas (clock, video, ephemeral data) and disclose all masked bounds.
- No viewport reference? Mark test **responsive QA**, not **reference match**.

## Manual score: 0–10, per referenced viewport

| Dimension | Weight | Criteria |
| --- | ---: | --- |
| Layout & geometry | 35% | section size, alignment, spacing, proportions, background coverage |
| Typography | 20% | matching family where known, text size, weight, wrapping, line-height |
| Assets & iconography | 20% | actual image/icon identity, correct crop and position, no missing assets |
| Responsive behavior | 15% | appropriate reflow and no clipped/overflow elements |
| States & accessibility | 10% | interactive behavior, focus, contrast, readable UI |

Each dimension gets a documented 0–10 mark; compute weighted overall `sum(score * weight)`. A numerical score is an assessed rubric, not a proof of perfect visual match. Target ≥9.5/10 only when measurable against provided references and all functional checks pass.

## Acceptance gates

- All user assets preserved unless specifically replaced.
- No severe visual discrepancy in header, hero, background, section boundaries or gallery.
- No horizontal overflow or unreadable text at specified widths.
- Icons consistent in stroke/weight, size and baseline.
- Font choices, size and wrap documented with evidence confidence.
- All screenshots, asset inventories, build/test results and unresolved discrepancies included.

## Iteration order

1. wrong/missing source asset or invalid CSS background;
2. misaligned section frame, grid, aspect ratio, hero crop;
3. incorrect font size/family, wrapping and line height;
4. spacing and component dimensions;
5. shadows, radii, minor icon positioning.

Stop only when target is evidenced or a real blocker is recorded. Do not invent screenshot captures or test outcomes.

## Mandatory visual demonstration (all completed runs)

1. Present **mobile and tablet side by side**, in one clearly titled image. No third miniature panel and no cropping of screenshots.
2. If the supplied source is a **desktop interface screenshot**, present **original desktop screenshot next to the rebuilt desktop capture**, labeled consistently. Match viewport, crop and state; any deliberate crop must be documented. If dimensions disagree, warn prominently and do **not** claim fidelity from that board.
3. If the source screenshot is not desktop, show the desktop preview without an invented desktop original. Compare other source breakpoints separately when applicable.
4. **Display the two images inline in the chat**, not just links, file names, descriptions, or external galleries. Prefer one board per message/section, and avoid wide multi-row contact sheets that become unreadable on a phone. Share high-resolution files as optional extras.
5. Require reproducible evidence generated by `python scripts/present_results.py ...`; preserve original screenshots, image proportions, and labels. Display only captures actually generated and visually inspected.
