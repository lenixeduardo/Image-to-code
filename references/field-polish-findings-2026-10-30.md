# Image to Code — Field polish register (Catty, Zouti, GoatVPN)

**Date:** 2026-10-30. **Scope:** Quality gates and incremental improvements derived from real local image-to-code tests. **Status:** Findings documented; implementation remains tracked in TODO.md. This file includes **no original screenshots, proprietary artwork, source fonts, or confidential data**.

## What actually happened (do not mistake tests for fidelity)

| Case | Proven result | Failure mode / limitation |
| --- | --- | --- |
| Catty, three dialog states | Browser interaction/text checks passed; pixel calibration mean SSIM increased from **0.3887** to **0.6269** | Correct text and navigation did not catch clipped phone/device controls, different cat expressions, hidden paws, unwanted screenshot edge halos, and icon/font mismatches. 75 passing checks did not mean pixel-perfect. |
| Zouti desktop collage (1045 × 668) | **0.7898** overall SSIM, but **0.4565** in headline/buttons reconstructed as HTML; screenshot-derived dashboard **0.9769** | Composite visual score was artificially favorable to preserved screenshot crops. Dashboard, feature cards, and editorial panels were not independent DOM components; the responsive views were inferred. |
| GoatVPN, clean HTML/CSS/SVG (1020 × 562) | **24/24** runtime checks passed, yet desktop SSIM was **0.4994** | Missing fidelity in big decorative background, globe dot density/arcs/nodes, device outline, phone UI, typography, and lighting; runtime success is not pixel accuracy. |
| GoatVPN background replacement | New asset raised SSIM **0.4994 → 0.5623** | Background positioning initially caused lettering intended for the outside canvas to intrude into the laptop. Phone/globe lighting and composition remain visibly off. A generated scene can be closer in style without being identical. |
| Preview handoff | Standalone HTML rendered in a compatible local Chromium environment, but was reported as not opening inside a ChatGPT viewer | A validated HTML file is not automatically an accessible live preview in the user's client. |

**Metrics caveat:** SSIM is a diagnostic signal, not a 0–10 grade. The cases above use different art and scene compositions and must **not** be directly ranked against each other. No automated checker or agent is certified as 9.5/10 because of these observations alone.

## P0 — Must-gate problems (improve before approving a reconstruction)

| ID | Observed issue | Required improvement | Acceptance evidence |
| --- | --- | --- | --- |
| **POL-001** | Image generated by AI was once presented as if it fulfilled an image-to-code task. | Distinguish `GENERATED_IMAGE`, `SOURCE_SCREENSHOT_CROP`, `SVG_REBUILT`, and `BROWSER_RENDERED_HTML` throughout artifacts and assistant claims. | Only a Chromium/WebKit screenshot produced from served code can be labeled HTML reconstruction; report includes render URL, viewport, browser and source policy. |
| **POL-002** | Hybrid page reused original pixels and inflated visual similarity (Zouti). | Enforce **zero source-screenshot crop** mode as the default in strict recreation projects, including CSS `background-image`, embedded data URIs and generated bundles. Source screenshot may be used for comparison only. | Asset provenance manifest and static scan flag exact/near-identical source fragments; exceptions require explicit user consent. |
| **POL-003** | Screenshot panels of dashboards, cards and phone were visually preserved rather than implemented. | Break nested UI into editable, accessible DOM/components with real charts, legends, labels, buttons, and state changes; allow illustrations as separate scene assets only. | DOM audit confirms required panels and controls are independently selectable; hiding asset images doesn't remove core UI. |
| **POL-004** | Background art visually deviated heavily from the original (GoatVPN). | Regenerate a **clean scene-only** art asset from the reference; separate base, geometric typography, mesh/globe, light paths, particles and surface glows. **Never** paste source screenshot pieces. | Distinct layers and per-layer reference/actual comparisons at reference viewport. Clean scene contains no duplicated baked-in interface text. |
| **POL-005** | Large lettering from background entered the laptop (GoatVPN background v2). | Add scene-boundary ownership and foreground occlusion masks anchored to device/container geometry, with responsive clipping rules. | No decorative art crosses designated device boundary across tested viewports, verified by pixel/geometry mask. |
| **POL-006** | Globe/network artwork had different dot density, routes, arc curvature and node positions. | Calibrate reference-normalized landmarks: globe radius/center, sampled point distribution, connectivity arcs, glow radii, node counts and depth hierarchy. | Export landmark JSON and overlay; critical landmark displacements within explicit per-project tolerance, not hidden by broad blur. |
| **POL-007** | Device frame and phone UI did not match notch, outline, tilt, rounded corners and layer depth. | Rebuild device geometry as an independent foreground component; control aspect ratio, border widths, corner radii, shadows, clip and overlap. | Matching normalized screen/device boxes; no clipping at 375/390/820/1020/1440; dedicated reference-vs-render close-up. |
| **POL-008** | Characters/paws and bottom controls were clipped despite successful functional tests (Catty). | Make visible anatomy and critical controls explicit `mustFit` subjects with occlusion and alpha-edge checks. | No cut paws, hidden control row, truncated device frame or missing ears in any required state. |
| **POL-009** | High overall SSIM concealed poor fidelity in recreated text/buttons. | Require provenance-separated scores for `pure code`, `new generated illustration`, and `permitted screenshot content`; separately score typography, CTA, hero subject, lighting and layout. | Report publishes per-region values, source policy and unscored/unknown regions; whole-frame metric cannot approve poorly matched critical regions. |
| **POL-010** | UI text and conversation states deviated or were invented in earlier iterations (Catty). | Preserve text, punctuation, case, line wraps and exact sequence as structured text contracts before generating markup. | Literal copy diff for every state; no extra/invented dialogue or hidden baked-in copy. |
| **POL-011** | Model selection between mockups was confused; Zouti image was generated during a GoatVPN correction. | Add mandatory project/reference identity gate (image hash, thumbnail and target name) before every generation or build task. | Asset provenance and render manifest reference only the active project's reference ID/hash; cross-project file is a hard failure. |
| **POL-012** | Agent/CLI and image generation outputs were sometimes mistaken for browser proof. | Gate claim language: tests pass ≠ pixel perfect; runtime install ≠ agent invocation; generated artwork ≠ DOM. | QA summary names evidence types and blockers; no high-fidelity claim without reference/render paired boards and runtime evidence. |

## P1 — Visual polish and robust delivery

| ID | Observed issue | Required improvement | Acceptance evidence |
| --- | --- | --- | --- |
| **POL-013** | Outer background typography, blue wave geometry and tonal balance differed. | Multi-scale luminance/edge/color comparison for **background-only** layer; calibrate blur kernel, wave direction and highlight falloff without generic gradients. | Background layer diagnostics (aligned pair, heatmap, distribution of highlights/edges), before/after deltas. |
| **POL-014** | Background masked with arbitrary dark overlays to conceal artifacts. | Protect original/generated clean-asset artwork from blanket blur/black patches; require visible mask overlays and bounded masked area. | No hidden excessive mask; <= existing mask ceiling and 0% masked critical CTA/face/logo regions. |
| **POL-015** | Font family/weight/line wrapping differ even when headline copy matches. | Font source/provenance check + browser fallback detection + title line-break/line-height/letterspacing width audit; preserve fonts only if licensed. | Font hash or `ORIGINAL_UNAVAILABLE` explicitly stated, with per-line bounding boxes and wrap diffs. |
| **POL-016** | SVG icons were merely approximations, with wrong fill/stroke, baseline or optical weight. | Add per-icon geometry tests, consistent viewBox and stroke standard; render original-reference icon alongside generated SVG. | Pass icon baseline/stroke/shape comparison, or mark unsupported original source. No decorative emoji icons. |
| **POL-017** | Pill buttons, secondary CTA, labels and spacing varied. | Use position/width/height/radius/padding tolerance gates per component in native CSS pixels, normalized to viewport and DPR. | Component geometry JSON and reviewer-approved correction proposals; critical CTA within configured tolerance. |
| **POL-018** | Visual focus differed as artwork moved while copy stayed still. | Calibrate hero typography, device, object, CTA and hero art together with constraints on their relative distances, alignment and overlap order. | Anchored layout metrics and close-ups for each semantic zone, not just a full screenshot. |
| **POL-019** | Cats’ expressions were not correctly matched between the three screens. | Assign **distinct scene and expression assets per state**, prohibit silent reuse of one expression as an all-purpose fallback. | State asset table, rendered comparisons per state; manual review of actual anatomy and texture. |
| **POL-020** | Cutout artifacts and artificial glow looked like gray/smudged edges. | Validate alpha premultiplication, edge feathering, hair/fur integrity and glow provenance; use scene-level regeneration rather than cropped screenshots for missing content. | Alpha matte preview on dark/light checkerboards; no rectangular halo or erased fine structures. |
| **POL-021** | Screenshot original was desktop, but mobile/tablet were inferred. | Mark breakpoint-derived layouts as `INFERRED`; never assign pixel-match scores for viewports without original references. | Responsive board annotated `INFERRED`, full no-overflow checks, accessible interaction and no fake reference comparisons. |
| **POL-022** | Side-by-side comparisons stacked in the user client or labels overlapped. | Generate **one composite PNG** for desktop original×render, and **one composite PNG** for mobile×tablet; correctly placed labels and readable scaling. | Visual board always displays as one image, with 2 aligned panels, no clipped header/label, and is presented directly in chat. |
| **POL-023** | HTML preview could not be opened in the user's viewer. | Ship a self-contained HTML, a standalone ZIP, and a documented local/HTTPS server fallback; test in `file://` and served HTTP when possible; no promise that ChatGPT viewer executes HTML. | Local Chromium opens both allowed delivery modes, assets load, interaction smoke passes; report platform-specific limitations. |
| **POL-024** | Functional interactions passed while some visual states were off-screen. | Combine `mustFit` geometry with interaction sequence and screenshot capture **after each** click/tab/swipe, including viewport scroll restoration. | Complete state-level browser trace, zero unintended clipping and no broken assets or JS errors. |
| **POL-025** | Desktop glows were stronger than reference and mixed with generated background illumination. | Prevent CSS double-glow over **baked-in lighting** in new illustration assets; use a light ownership list per layer. | Same lighting origin appears once; no extra haze surrounding subject or phone. |
| **POL-026** | Uncertain original source or flattened screenshot had occluded pixels. | Track `CONFIRMED`, `INFERRED`, `NEWLY_GENERATED`, `UNRECOVERABLE` at asset/region level; never label regenerated pixels as original recovered files. | Asset manifest with source and confidence; exact reconstruction claim blocked for unrecoverable zones. |
| **POL-027** | Visual metrics sometimes improved only slightly despite large-looking edits. | Store **before/after** full and semantic-region diagnostics for each iteration and rollback if critical-region score worsens, even when global SSIM increases. | CI trend shows both full and critical-region deltas, regression reasons and previous version. |

## P2 — Process and automated review ergonomics

| ID | Observed issue | Required improvement | Acceptance evidence |
| --- | --- | --- | --- |
| **POL-028** | QA handoff lacked a single one-click detailed region explorer. | Bundle a local report with split overlay, region hotspots, dimension/font/icon diagnostics and original/live view selectors, without exposing private assets. | Reviewer can compare zones at 1:1 and inspect critical mismatches in the bundled report. |
| **POL-029** | Reviewer notes were not automatically translated into actionable tasks. | Map issue IDs → region → probable cause → candidate CSS/SVG/asset change → severity and owner; proposals remain reviewer-approved before changes. | Deterministic machine-readable checklist and traceable change log. |
| **POL-030** | Benchmarks had different reference qualities and some used screenshot fragments. | Maintain separate strict crop-free and hybrid experiments, and benchmark with at least three independent owner-approved projects. | Aggregate real-project false-positive/negative data; report missing reference dimensions and source policy explicitly. |
| **POL-031** | Browser tests were not enough to establish model-agent portability. | Run full image→assets→DOM→browser→iterations flow under authenticated Claude Code/Codex/OpenCode/Hermes/etc., using the same hidden reference and metric schema. | Per-agent reproducible execution logs, no hardcoded result reuse, and browser evidence. |
| **POL-032** | Small interface and responsive errors can be overlooked when QA boards are wide or images low-resolution. | Capture source-size screenshot with explicit DPR, provide local high-res close-ups and independently inspect regions prior to summary. | QA outputs state resolution/DPR and show text/icons at useful zoom without distorting target pixels. |

## New recommended acceptance flow (not all automated yet)

1. Lock the active project and source image SHA-256; inventory reference dimensions, intended output type, source-crop policy and available original assets.
2. Extract **specifications** and geometry; when strict no-crop, generate new clean layered scene assets using reference guidance and verify provenance. Do not treat raster screenshot regions as deliverable components.
3. Produce accessible real DOM components with exact text and independently inspect nested app/dashboard content.
4. Run browser captures at original dimensions/DPR, plus inferred mobile/tablet. Capture *each state* with critical geometry gates.
5. Compare independently: background/lighting, subjects/anatomy, device geometry, text and CTA, icons, and internal app panels.
6. Record and inspect per-region SSIM/MAE and explicit source provenance; show single-file side-by-side boards **directly in the conversation**.
7. Make a reviewer-approved next-iteration plan. Repeat and block approval while critical zones differ or are missing, despite passing runtime checks.
8. Export working HTML/ZIP, static capture boards, quality report and TODO; clearly disclose that HTML preview support depends on client and that unprovided viewports are inferred.
